# 2層ストレージ：構造化テーブル＋キャッチオールテーブル

OTLP レコードの保存を「構造化テーブル（長期）」と「キャッチオールテーブル（7日間）」の2層に分ける。

構造化テーブルはクエリ・分析用のビューとして長期保持する。キャッチオールテーブル（`raw_logs` / `raw_metrics`）は既知・未知を問わず全レコードをフル JSON で受け取り、未知イベントの発見や既知イベントへの新属性追加の検知に使う。7日を超えた行は Cron Trigger で日次削除する。

構造化テーブルに `raw` カラムを持たせると「スナップショット」に過ぎず真の生データではない上にキャッチオールと役割が重複するため、構造化テーブルの `raw` カラムは廃止した。

## Considered Options

- **構造化テーブルに `raw` を残す** — 既存の設計。スナップショット（個別レコードの JSON）であり真の生データではなく、誰も参照していなかった。
- **キャッチオールのみ（構造化テーブル廃止）** — 却下。構造化テーブルは分析クエリ用のビューとして必要。
